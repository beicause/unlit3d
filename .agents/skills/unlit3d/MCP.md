# 用 MCP 检查运行中的 world

**用途**：为 agent 选择宿主、发现工具并取帧。前提是可运行的宿主和可用的 MCP 客户端；客户端安装、认证和 daemon 行为由环境的 `mcpdo` 技能或实际帮助负责。此页不定义工具参数，最终以 `tools/list` 为准。

## 服务器与驱动

- **stdio** 由客户端启动宿主进程；多步检查应复用同一条已就绪连接。**HTTP** 连接已运行的宿主，使用日志报告的地址；相关支持由宿主和 feature 决定（多 world app 使用 `mcp-http`）。[启动命令](EXAMPLES.md#跑起来调起来) 里有不依赖窗口的按帧宿主。
- 先确认 `tools/list` 返回所需能力，再调用。缺客户端则报告并使用已获准的客户端，或请用户确认安装；权限拒绝按环境审批流程处理，不改 `HOME` 或其他路径规避。待认证不代表连通。自动重连可能新起 stdio 进程；发现重启后重新定位 world、资源与当前帧。
- 窗口、显示协议与 GPU 环境由本机运行指引负责；不把某个显示名称写成固定值。要不依赖窗口，优先用无头宿主。
- 传输和驱动独立：`--interactive` 让客户端推进；自驱宿主可能在两次调用之间前进。宿主必须泵命令，自定义无头宿主检查 `pump_mcp` 的调用位置。

## WorldRef 与世界名

从 `list_worlds` 的返回取 world 引用，再在该 world 用 `list_resources` 或宿主状态定位目标；`Host` 不是渲染 world 的通用别名。不要复用其他会话的句柄。工具失败先检查结构化错误与对应 world，再决定是否重试；不要把失败当空结果。

## 工具清单

按任务查本次连接的 `tools/list`：实体与组件用 world 查询组，渲染资源用资源图组，模拟推进用宿主控制组，录音用音频组。组件是否可序列化、工具是否可见，都受宿主与 feature 影响；不要从其他宿主的工具列表推断这里也支持。

### 绘制

| 需要先重新渲染吗 | 内联小图 | 落盘（大图优先） |
| --- | --- | --- |
| 否，读已有纹理 | `read_texture_as_image` | `save_texture_as_image` |
| 是，再读取指定目标 | `read_screenshot` | `save_screenshot` |

目标必须是所选 world 中可读回的纹理（`COPY_SRC`）；截图工具还接受该纹理的视图。交换链图像通常不在资源图里；需从窗口取图时先核对是否走常驻中间目标。落盘目录是**宿主进程**看到的路径，检查工具返回的路径；远端宿主的路径不等于客户端本地路径。重绘是渲染，不自动等于一次完整模拟步进。

## 按帧驱动

1. 连接由 `--headless --interactive` 启动的宿主，确认 `step_frames` 和所需的纹理工具可用。
2. 用宿主状态或帧时钟确认当前帧，必要时注入输入，然后推进所需步数。按返回中实际推进的步数判断完成；达到帧预算时返回值可以小于请求值。
3. 从状态/资源清单取本次输出纹理的 ID，不猜参数。要保留刚生成的帧，按[取图表](#绘制) 用 `save_texture_as_image`，而不是另渲染再保存。
