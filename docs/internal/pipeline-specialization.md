# 运行时管线特化与缓存

本文说明渲染管线的特化与缓存如何设计，以及为什么它不是一个"编译好的组件"。
面向对比 Bevy 的 `Variants` / `SpecializedRenderPipelines` 的读者。

## 问题：管线依赖两个运行时才知道的东西

一条已编译的 `wgpu` 渲染管线在创建时就固定了全部状态，其中两项只在实际绘制时
才知道：

- **渲染目标**：颜色格式、深度格式、采样数随帧而变（外部 `TextureView` 与自有的
  附件集不同）。
- **网格顶点布局**：逐实体、逐网格，决定顶点状态与是否读取压缩通道。

因此"实体持有一条已编译管线"是错的：同一份材质与几何可能因目标或网格布局不同
而需要不同的管线。反之，这两个维度完全相同的一组绘制应共享一条管线。把这两个
维度做成缓存键，就得到一个自然的 `key -> pipeline` 特化缓存。

## 分层：通用设施与使用者

特化/缓存是**通用设施**，与 unlit 无关，因此放在 `unlit_wgpu` 的
`specialize` 模块，且**不依赖 `unlit` feature**。它不关心"什么是管线"，
只要求一个类型能：

- 从描述符创建，
- 报告自己由哪个描述符创建而来（用于调试期校验缓存正确性），
- 由一个纯函数把"小键 + 描述符"改写为特化后的描述符，并给出该键的规范形式。

内置 unlit 只是这套设施的一个普通使用者，没有任何特权入口；自定义管线的用户
用同样的路径接入。

## 缓存：两级、惰性编译、不淘汰

缓存以键为索引，每个键最多产生一个值。键到值有"多个键归结为同一规范形式"的
情况（例如两个网格的原始属性不同，但推导出的着色器标志一致），因此分两级：

- **主键 -> 变体**：每次特化先查这里，命中即返回。
- **规范键 -> 变体**：主键不是单射时用它去重，使语义相同的绘制共享同一条管线。

设计取舍：

- **蓝图由每次特化时提供，而非注册时存一份。** 蓝图属于实体（见下），缓存只负责
  去重；命中时不应产生任何克隆。
- **描述符本身不作为哈希键。** 它包含浮点编译常量，而浮点无法在不破坏
  `Hash`/`Eq` 契约（`0.0 == -0.0`、NaN）的前提下哈希。替代做法是让特化键携带
  实体的身份，使"值相同但浮点不同"由键区分，而不是去哈希描述符。
- **编译惰性**：注册一个家族不编译任何东西；首次有绘制解析到某个键时才编译。
- **不淘汰**：键的集合被假定有界（一个家族每个见过的目标/布局一份），保留简单性。
  调试构建下会复核规范键对应的描述符，若两个不同描述符映射到同一规范键即断言，
  提示特化函数使用了不该使用的键信息。

## ECS 侧：组件携带的是"特化请求"

`unlit3d` 中网格与材质是组件，管线同理：每个可渲染实体携带一个
`GpuPipeline<Key>`，其中 `Key`（`PipelineKey`）是**该实体自己的特化请求**，
它同时提供该请求的起始蓝图。组件不持家族句柄，也没有整数下标。

- **按类型找到家族**：家族以其键类型为身份注册，于是渲染器可以直接从组件的
  类型查到对应家族，无需向实体发放句柄，也无需在渲染器里维护"句柄 -> 家族"
  的旁路表。同一键类型重复注册是编程错误。
- **没有默认家族**：实体必须显式携带该组件；缺失的实体在可见性收集时被静默跳过。
  这避免"忘记设置管线就画出一条错误管线"的隐蔽行为。
- **逐帧解析**：家族每帧把实体的键与当帧的目标、网格布局组合成完整特化键，
  在缓存中解析出具体管线。目标或网格布局变化自然导致重新特化。

## 单态化收集

ECS 组件是具体类型，渲染器无法用一个静态查询遍历"任意键类型"的实体。因此每个
家族注册一个**按自己的键类型单态化的收集闭包**：它直接查询携带该键类型的实体，
解析管线并追加到本帧的可见列表。渲染器只遍历已注册的家族，与具体的键类型解耦。

这保持了 `unlit_ecs` 的通用性：不需要为"按运行时 `TypeId` 读列"新增接口，
也不需要把绘制顺序、排序等渲染知识下推进 ECS。

## 绘制顺序与不变量

每帧收集后对可见项排序一次，然后单次线性扫描发出绘制：

1. 不透明在前、透明在后；
2. 同类别内按具体管线分组，使相邻绘制尽量不切换管线；
3. 不透明项再按材质分组以复用绑定组，透明项按相机距离由远及近。

反向 Z 深度测试，单个 render pass 完成不透明与透明绘制。

## 非目标

- 不做全描述符缓存（见上文的浮点原因）。
- 不做运行时管线热重载、异步编译。
- 不给内置 unlit 任何专用路径；它和自定义管线走同一套注册、解析与缓存。
